# Plugging things in (hardware, services, accounts)

This guide covers the currently implemented extension seams and known dependencies; it is not a promise that every listed integration is production-ready. Configuration is sufficient only for an existing catalogue entry that supports the connector profile. A new provider adapter or catalogue entry requires a code/package change.

| What | Where it plugs in | What you do | What you see |
|---|---|---|---|
| A home hub, travel, work, shopping, messaging or cloud-storage service | **Connections** in the app; `connectors.json` (catalogue) and the connector profile (`CONNECTOR_PROFILE.md`) | For an existing profile-compatible catalogue entry: open Connections, press Connect, and enter its address and token. A vendor-specific API or a new integration ID requires a developer to add an adapter and/or catalogue entry; users cannot register arbitrary connectors at runtime | The integration with what it can read, what it can change, which changes ask you first, what happens offline; Connect, Check, Disconnect |
| Calendar, Contacts, Notes, Photos on the Mac | Settings, turn the source on | Allow the macOS prompt once | The source in Settings; its content in answers and the Library |
| Finance | `maintenance import-finance` and Settings | Import the supported legacy `transactions` table, then enable Finance | Finance summary/area; broader tables and real account connectors are not implemented. Health | Settings / empty encrypted store | No Health importer or HealthKit/native Health source is implemented; an enabled empty area is not evidence of ingestion | Health area explains empty/not configured state |
| The local model | `models/` folder with the signed manifest and `manifest.pub` (G-O12) | Copy the model and the key | Answers instead of "the local model is unavailable" |
| App updates | Put the release-signing public key at `~/Library/Application Support/Atlas/release.pub` | Place the key | **Updates** in Settings: Install an update, Go back |
| Signing and notarisation | `scripts/sign_and_notarize.sh` with `DEVELOPER_ID` and `NOTARY_PROFILE` | Run it with your Apple Developer ID | A notarised app |
| Browser reading | Core web route and isolated browser worker | Production host currently sets `web_engine=None`; remains OFF until OS-enforced worker confinement is accepted | Not available in the production host today |
| Voice | Nothing to plug in | Allow the microphone and speech recognition once, the first time you press the microphone button | A microphone button in the composer; speech stays on the Mac |
| Web reading | Off until the browser worker runs under OS confinement; then the Web screen, and the packaged app carries the browser when built with `ATLAS_BUNDLE_BROWSER=1` | Allow the sites you want; read a page | Page text marked untrusted, with its source and time |
| The iPhone | The iPhone app (`ios/`, built with `xcodegen`) and the pairing invite; the remote channel is your choice (G-O14): save a private or VPN address in the Mac's Settings (for example your Tailscale address and a port) | On the Mac: Settings, enter the address your phone will use, Show pairing code. On the phone: scan or paste it | The phone's Ask and Areas; Devices in the Mac's Settings, where you can remove it |

Rules: the owner connects and disconnects only from an enrolled owner client; credentials are stored in the Keychain; a service that does not answer is shown as needing attention, never as connected. Disconnecting must revoke capabilities and delete credentials. The connector undo and `.ts.net` transport risks in `CONNECTOR_PROFILE.md` remain open; do not treat the generic connector seam as a verified vendor integration.
