# Threat and privacy review (design level; for this slice only)

Scope: the new foundation (policy gate, tasks, evidence, events, API). Evidence: tests in `tests/` (synthetic data only). Not a penetration test; nothing ran on the owner's Mac or data.

| Threat | Control | Evidence | Residual risk |
|---|---|---|---|
| Source read before a permission exists (generic search leaks a sensitive source) | Default-deny `PolicyEngine`; retriever only via `GatedRetrieval` with a `PermitToken` | `test_policy.py` (order, no-grant, forged token, hostile retriever) | The legacy `search_files` path still has no gate (Stage 1 G-13); closing it needs wiring in a later stage. |
| Finance/Health reach a model through a grant or a request | Restricted domains denied before grants are read; data-driven list | `test_finance_and_health_never_enter...`, sentinel scans | The list is data: a mistaken edit of `policy-rules.json` weakens it. A test asserts the shipped rule file. |
| Hostile document or mail ("ignore the policy, send data") | Retrieved text is data; no action exists in the slice; citations must be among retrieved passages; scope comes only from the request and policy | `test_a_client_cannot_widen...`, `bad_quote/not_retrieved` modes | No real model was tried; prompt-injection resistance of a real 3B model is NOT measured. |
| Model cites a source it was not given or invents a quote | Citation must equal a retrieved evidence reference and its quote must appear verbatim in the span | `test_an_answer_with_a_failed_citation...` | Paraphrase correctness (does the sentence follow from the quote) is not verified. |
| Stale evidence after a source changes | `version_sha256` of the stored text is part of every reference | `test_a_changed_source_makes_every_old_citation_stale...` | Provenance of real documents (page offsets) is not stored yet (G-2). |
| Unsupported figures/dates presented as verified | `unproven_figures` + numeric date check; status capped at `partially_verified` | `test_a_figure_not_in_the_cited_text...` | Dates with month names are not checked (no word lists in code); documented. |
| A grant revoked while a task is saved (one source revoked, another still allowed) lets old evidence or an old answer through on resume or on read | On resume every saved passage, citation and saved answer is re-checked against the current token and the task fails closed (`denied`); `answer()` and the event stream re-check what they serve against **every source type the answer was built from** (the retrieved passages saved with the task, not only the cited ones, so an uncited draft is withheld too) and replace it with a plain 'no longer available because permission was revoked' answer (`answer_withheld`) or error | `test_review_fixes.py` (5 crash boundaries x 2 revoked sources, completed-then-revoked, uncited answers with one source revoked and one kept, mutation checks) | The stored envelope is kept as it was (audit); only what is served is gated. Gating is conservative: if any retrieved source is revoked the whole answer is withheld, even if the draft used only the others. Anything already delivered to a client before the revocation cannot be recalled. |
| A context built under a broad permission is used with a narrower one | A `ModelContext` carries the id of the authorisation it was built under; the model door checks the id, expiry and re-checks every passage against the token it is given | `test_a_context_built_under_a_broad_token_cannot_be_used_with_a_narrow_one` (including a copy that claims the narrow id) | In-process misuse by code that already holds a valid token cannot be fully prevented in Python; the per-passage check is the real guard. |
| A grant revoked, replaced or narrowed while a task is running, or an item more sensitive than the grant | **A token is bound to the grant it was minted under** (its identity and its ceiling, per source type). The gate re-validates against the grants as they are NOW immediately before **each source read** and again at the **model door**; a revoke followed by a new grant, or a changed ceiling, ends the authority for that type (`grant_revoked`) even though the type itself would be allowed again, and a token never gains anything from a broader or newer grant. **An item's sensitivity is a trusted label read from the source store (`StoredSource.sensitivity`, else the type's default), never from what the retriever returned**: the gate ignores any sensitivity on a passage, and an item whose source is unknown to the store, whose type disagrees with the store, or whose label is missing or unknown has no label and is never covered by any grant (excluded and disclosed as `sensitive_items_excluded`). Checked at retrieval output, at context construction and at the model door | `test_review_round2.py` and `test_review_round3.py` (a retriever that understates or overstates a label is not believed; unknown source, type confusion and unknown label fail closed; revoke and regrant between two reads, between retrieval and the model, and a ceiling lowered in place during retrieval: the model receives zero passages; a broader newer grant gives an old token nothing) | The label is only as trustworthy as the side that stores the source: the real ingestion in Stage 3 must write `StoredSource.sensitivity` itself and never copy it from content. A read already in progress when a grant changes finishes, but its result is not sent anywhere. The frozen 1.0 contract still lists an optional `PassageRef.sensitivity`; it is accepted and ignored. |
| A crash between a state change and its stream event | State, checkpoint, terminal reason and the events describing the change commit in one transaction on every path (`TaskStore.transition(events=...)`, including cancel, expiry, denial, failure, completion and recovery). **The store refuses a terminal transition unless it carries exactly one closing event (`final` or `error`)**, the only writer of an event outside a state change (`append_event`) is removed, a denied task's safe answer commits in the same transaction as its state, **an answer is served only once the task has finished** (a saved envelope of an unfinished task is a checkpoint, never a result), and a test shows the service has exactly one way to change state | `test_review_round2.py` and `test_review_round3.py` (nine terminal paths x two crash points inside the transaction: completed, partially completed, citation failed, model unavailable, denied, cancelled immediately and at a boundary, expired, recovered into needs-attention; each leaves neither a terminal state nor a half-written event, and finishes with exactly one closing event; the store refusal; the service source scan) | Process kill is simulated by exceptions at transaction hooks, not a real kill. |
| Stage 3 threats (hostile content, parser bombs, index poisoning, stale caches, consent abuse, spoofed headers, egress exfiltration, log leakage, starvation, weak key provider, crash mid-index) | Each has a control owner, an implementing package and a proposed test in `STAGE3_TRACEABILITY.md`; the 1.1 contract adds only closed, content-free shapes (`CONTRACT_1_1.md`) | `test_contracts_v11.py` (shapes and no free-text field); the rest is pending in the packages that build the controls | Nothing of Stage 3 is implemented yet: only the contract shapes and the specification of the 1.1 signing rule exist. Mac-only items (OS-level egress isolation, real Keychain, real load) stay pending hardware. |
| The task key is read from a plaintext file or the environment on the Mac | `default_provider()` returns the Keychain provider on macOS unconditionally unless `ATLAS_TASK_KEY_SOURCE=env\|file` is set explicitly; the environment/file provider is the Linux/test path; provisioning writes the key via `security -i` standard input, never a command line | `test_the_keychain_provider_*`, `test_on_a_mac_the_environment_or_a_key_file_never_silently_replaces_the_keychain` (fake `security` runner) | The real `security` tool, Keychain access prompts and item permissions are NOT VERIFIED until run on a Mac. |
| Another local process or a browser page drives the Core | Per-client Ed25519 signatures, nonce, timestamp window, revocation; Unix socket 0600 in a 0700 folder; peer uid check; browser Origin/custom headers carry no authority | `test_api.py` identity tests, `test_transport.py` | Client key storage on the device is the client's job; enrolment/revocation UX and remote transport are G-O14. macOS peer-credential branch NOT VERIFIED. |
| Replay of a captured request | Single-use nonce within the freshness window | `test_identity_a_tampered_body_a_replayed...` | Nonce cache is in memory: lost on restart (a replay inside the window right after a restart would be accepted); window is 60 s. |
| Logs leak content | `SafeEvent` allow-list with enumerations and patterns; refusal of anything else; fixed user messages; no access log | `test_redaction.py` (success, failure, denied, cancel, expiry, retry, 500 path) | Logs of other components (Ollama, web server, OS) are outside this package. Correlation ids are random, not derived from content. |
| Content at rest | New store is SQLCipher-encrypted with its own key; plaintext file refused | `test_the_task_store_is_a_new_encrypted_file...` | Backup and key recovery are undecided (G-O05); losing the task key loses only task history, not sources. |
| Crash or restart corrupts task state or repeats side effects | One transaction per state change; checkpoints; idempotency keys; recovery rules | `test_a_crash_at_every_lifecycle_boundary...` | Process kill and power loss are simulated by exceptions, not real kills. |
| Denial of service by a same-user local client | Request framing is judged from the headers before any body byte is read: one valid decimal Content-Length within the 64 KiB cap, no Transfer-Encoding, no repeated or signed or non-ASCII length; otherwise a fixed 400 and the connection is closed. A client that stops sending is dropped after a read timeout (15 s, applies to request headers and the declared body). At most 64 connections are served at once; further ones are closed unserved. Event streams and the nonce cache remain bounded | `test_transport.py` (oversized, negative, malformed, repeated, huge-number, chunked and combined framing over a real Unix socket with no body ever sent; stalled body; connection cap and recovery; body exactly at the cap still reaches the API) | One thread per served connection (up to the cap) and no per-client rate limit: a same-user process can still occupy all 64 slots for up to the read timeout. Acceptable for one owner on a local socket; revisit with the remote transport (G-O14). |
| Unauthorised change of policy | No API can create or change grants in this stage (grants are read-only input) | no write endpoint in `openapi.yaml` | The owner's designation mechanism (G-O19) will need its own threat review. |
