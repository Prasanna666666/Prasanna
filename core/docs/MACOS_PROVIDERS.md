# The macOS providers a real Core needs (written, UNVERIFIED on a Mac)

A real Core is built by `host.build_config` (`python -m atlas_core.serve`, started by the app's `CoreLauncher`). Every Mac-specific part is behind a seam that CI exercises with a fake; the real thing has **never been run on a Mac**. Nothing here reads a real mailbox, a real Keychain or a real TCC decision in CI.

| Need | Implementation | Verified how | NOT verified |
|---|---|---|---|
| A key of its own for each store (task, designation, documents index, mail index, model record) | `macos.KeychainItems.secret` over the `security` tool (value to `security -i` on standard input, never a command line) | `tests/test_macos.py` with a fake `security`: distinct 256-bit keys, created once, read back, value never in argv, failure is content-free | the real `security` tool, Keychain access prompts and item access control |
| Rollback anchor outside the designation database | `macos.KeychainAnchor` (one JSON item); the two-phase rules are `designation.RecordAnchor`, shared with the CI fake | the same contract tests as the fake, restart persistence, an unavailable Keychain fails closed (`OSError`), a restored older database is detected | the real Keychain's behaviour under backup/restore and iCloud sync (the item must be this-device-only; not set here) |
| OS permission evidence | `macos.FolderPermissions`: can this process list the folder right now (EPERM is a refusal, a missing folder or any other error is no evidence, nothing cached) | Linux, folders and a forced `PermissionError` | real TCC behaviour (Documents, Full Disk Access for Mail), prompts and their timing |
| Apple Mail reader | `macos.EmlxMailbox` (`.emlx`: byte count, RFC 822, plist ignored); newest first, paged, symlinks never followed, only the five stored fields, **only text/plain parts, attachments never decoded** | synthetic `.emlx` files, the mail index over it, duplicate Message-IDs, oversized and malformed files | a real Mail store (layout by version, `.partial.emlx`, `.emlxpart`, IMAP/Exchange accounts, a Mail that is open) |
| Signed model manifest installed with the app | `host.load_manifest`: signed manifest + public key next to the models; missing, altered or unsigned gives **no models**, never an unsigned one | `tests/test_macos.py` | where the key and manifest are installed (packaging) |
| Local model engine | `MlxRuntime(IsolatedEngine("mlx"))`: the isolated worker (seccomp on Linux, `sandbox-exec` on macOS, `docs/MODEL_RUNTIME.md`) | fake engines on Linux | real MLX, the macOS sandbox profile, speed/memory/quality |
| Start the Core and hand the app its first-run code | `serve` + `CoreLauncher` / `launcher.CoreProcess` (`docs/ENROLMENT.md`) | `tests/test_launcher.py` with a real child process | the Swift launcher, packaging the Core into the app |
| Whole Core from these parts | `tests/test_macos.py::test_a_whole_core_built_by_the_host_indexes_documents_and_apple_mail_after_consent_and_purges_on_withdrawal` | Linux, fake Keychain, synthetic folders | all of the above on a Mac |

Source type names ("documents", "mail") are passed in (`--documents-source NAME=FOLDER`, `--mail-source NAME=FOLDER`); the policy rules stay the only place they are defined. A Core with no installed manifest still starts: answers then say the local model is unavailable while the typed functions continue.
