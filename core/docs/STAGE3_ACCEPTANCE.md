## Known limitations, consolidated
1. The SwiftUI app compiles and its tests pass on a macOS runner, and its launcher and client are exercised against the real Core there, and the packaged app is launched in hosted CI (Core start and stop with the app), but no person has used it as an app; TCC prompts, signing, FileVault and power-loss behaviour are not verified.
2. Only a tiny public model has been loaded (to prove MLX loads and generates inside the sandboxed worker on a macOS runner): speed, memory, quantisation quality, real prompt-injection resistance and non-English answer quality of the owner's models are unmeasured. Claims about the model line-up remain the owner's recorded decisions, not measurements.
3. Criterion 5 now has the G-021 policy path (synthetic); no Finance or Health source adapter or owner grant flow exists yet. Criterion 7's exactness is PARTIAL: deterministic validation is present, but high-precision terminating fractions can be rounded by the default Decimal context and mislabeled exact (ATLAS-EXACT-106). Letting the model call a typed tool during an answer is not built (no tools exist in this slice) and is not required by the plan's wording.
4. Consent and index status are served (owner-only, replay-protected, audited); `newest_indexed` is always null. First-run owner enrolment is served and tested with the Python client, guarded by a single-use code that only the process starting the Core knows (`docs/ENROLMENT.md`); this is **not platform-attested app identity** (still required before any public release), the launcher that starts the Core and hands the app the code is built and tested in Python with a real child process (`tests/test_launcher.py`) and in Swift, where the real `CoreLauncher` and `CoreClient` are exercised against the real Core on a macOS runner (start, enrol, shutdown, restart, relaunch after a crash, stale socket and pid file); the Mac providers a *real* Core needs (Keychain keys, Keychain anchor, folder-permission probe, Apple Mail reader, signed-manifest loading, isolated MLX engine) are tested with fakes and, for the Keychain, the production Core process and the sandboxed MLX worker, against the real thing on a macOS runner (`docs/MACOS_PROVIDERS.md`); **real TCC prompts and a real Apple Mail store have still never been touched**; the packaged app has been launched in hosted CI with Core start/stop checked, but no person has completed a UI/accessibility walkthrough. The package is ad-hoc signed only (not notarised), and a standalone Python runtime/model installation is not complete, so the app is **not yet owner-tryable**.
5. Retrieval is lexical; Japanese and other unspaced scripts are not retrievable (recorded in the evaluation as a known gap). Search reads only items that contain a query word (term index); the index is about 5.5x larger than before.
6. The public-web egress gateway exists (`docs/EGRESS_GATEWAY.md`: https-only, public destinations only, taint-aware refusal of private content, untrusted-data results, redacted audit, one-door architecture test) and is tested with synthetic fixtures; it is **wired through the Core answer path** (`POST /v1/tasks/{id}/research`, API 1.1 additive) behind two explicit gates that are both off by default (`CoreConfig.egress`, `CoreConfig.live_network`), so a default Core makes no outbound request; it has never touched the real Internet.

**Criterion 6** is MET-L as written: attachment bytes are not read. The reader makes one-byte reads and stops at the header end and the MIME delimiter; a non-text part before the first text part makes the message unreadable. Evidence: `os.read`-instrumented tests in `tests/test_macos.py` (short text plus small attachment in one 4 KiB window; header block; listing; attachment before text; nested multipart; truncated message; multipart without a boundary), the swap-between-list-and-read tests, and the Message-ID check on the bytes actually read.

**Egress guarantee (bounded, no more):** before a request, text (the query; for a URL its host labels, path, query, fragment and every redirect hop) is decoded (percent-escapes, also twice; compatibility forms; accents; camelCase; underscores) and refused if it holds an identifier-like value, any word of 4+ letters of a private passage (English and Dutch function words exempt), a two-word run of a passage, a four-word run of the question, or a capitalised name from the question; a task with Finance or Health data in scope or context may not use the network at all. Fingerprints only: raw private text is neither stored nor logged. **Residuals:** a paraphrase, and words or names of 1-3 characters, are not guaranteed caught; the gateway over-refuses deliberately. This is **not** a general no-private-egress guarantee, and it has never been exercised against the real Internet.

- **F-4** selected-production-model injection evaluation with an accepted threshold.
- **F-11** owner-machine and owner-model verification of the sandbox (and any least-privilege tightening beyond what a hosted runner allows); real-Internet exercise of the egress gateway; explicit owner decision to turn the live-network gate on. Public search stays disabled until then.
- **F-12** real-model, target-hardware latency, memory, thermal and quality measurements against thresholds the architect and owner accept (proposal: `evals/thresholds_proposed.json`).
- **F-13** human UI and accessibility walkthrough; real TCC prompts; real Apple Mail store; Developer ID signing and notarisation; self-contained Python and model installation, upgrade and rollback.
