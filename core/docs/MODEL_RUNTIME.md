# Model runtime: verified loading, yielding, isolation (WP3.4)

Most of this is verified on Linux with fake engines and stubs. On a GitHub-hosted macOS runner (Apple silicon, the CI `macos` and `macos-mlx` jobs) the real `sandbox-exec` profile and a **real, small public MLX model** (`mlx-community/SmolLM-135M-Instruct-4bit`, chosen only to prove loading) have also been run in the worker. **Nothing is claimed about the speed, memory or answer quality of the models the owner will use, about the owner's own Mac, or about the prompt-injection resistance of any model.**

## Verified-only loading (`models.py`)
- A signed manifest lists every approved model (hash of every file, lineage, licence, runtime, capabilities). A model not in it never loads; only safetensors/GGUF weights plus configuration and tokenizer data are accepted; no pickle, no code.
- Every path is opened **one component at a time with `O_NOFOLLOW`** from an open directory descriptor (a symlinked parent cannot redirect a manifest path out of the model folder, nor can the model folder itself be a link) and every digest is computed **from the open descriptor**.
- `stage()` builds the folder the runtime loads from: **only the manifest's files**, as hard links to the verified inodes (so a later rename or replacement of the original name cannot change what loads), each confirmed to be the inode that was hashed; where links are impossible a copy is hashed as it is written. Unmanifested files next to the weights are never visible to the loader. `still_verified()` detects an in-place change after loading; a staging folder is removed on unload and any left by a crash at start.
- Threat model: other processes and accidents. A process of the same user that deliberately rewrites a read-only file and its timestamps is not defended against.
- Tests: `tests/test_models.py` (parent symlink, deeper component, folder as link, extra files, rename after verify, in-place change, swap between verify and link, copy fallback, crash leftovers).

## Yielding and bounded waits (`intelligence.py`)
- Runtimes poll `should_stop` between pieces of output. Interactive requests never yield. A **background** inference stops (the caller gets `ModelUnavailable("preempted")` and may retry) when an interactive request is waiting for a different model or when memory pressure holds background work (`stop_background`, `pause_background`).
- An interactive request that needs another model waits at most `SWITCH_WAIT_SECONDS`, then `busy`; the scheduler admits one interactive plus one background inference.
- The memory need is the weights plus `context_tokens x kv_bytes_per_token` (`kv_bytes_per_token` is injected; **unmeasured here**, to be set from the Mac benchmark), so the `shrink_context` step really lowers it, and the smaller context is what runs.
- Tests: `tests/test_intelligence.py` (interactive arrives during a running background inference and progresses in well under the background job's natural duration; memory hold stops a running job; same-model interactive does not stop it; bounded wait; shrink lowers the need and the smaller context is used).

## Local-only boundary (`sandbox.py`, `worker.py`, `isolated.py`)
- The engine runs in a **separate worker process** that installs an OS network denial **before importing or loading anything** and reports it in its first message; a worker that cannot is never used (fail closed). Linux: a seccomp filter (no_new_privs) makes `socket()` fail for every domain except AF_UNIX and blocks `io_uring_setup`; it cannot be removed and is inherited. macOS: the worker is launched under `sandbox-exec` (from `/`, not the caller's folder) with a profile that denies every network operation, every file write except `/dev/null`, **reading the places private data lives** (`/Users` — every home with Documents, Mail and browser data —, `/Volumes`, `/private/tmp`, the temporary folders, root's home) except the staged model folder and the Python runtime's own folders, executing any program outside the Python runtime, and every Mach lookup except a measured list of ten services (see below). **CI-verified on a macOS runner:** TCP connect and UDP send are refused (a receiver sees nothing, an unconfined control sees it), Unix sockets and pipes work, file writes to `/tmp` and the home folder are refused, a home-folder sentinel, a `/tmp` sentinel and `~/Library` cannot be read while a file in the model folder can, `/bin/echo`, `/usr/bin/curl` and `/bin/sh` cannot be run, name resolution gives no answer, and the real MLX library loads the model and generates inside it **with every Mach lookup denied except ten services** (`sandbox.MACH_ALLOWED`: `coreservicesd`, `MTLCompilerService`, `analyticsd`, `cfprefsd` agent and daemon, `logd`, `lsd.mapdb`, `system.notification_center`, `opendirectoryd.libinfo` and `.membership`). The list was measured on the macOS runner (every lookup allowed with reporting on, a load and a generation recorded, then a deny-all-lookups profile with only those allowed was required to generate); the known network-capable services in `sandbox.NETWORK_SERVICES` are not in the ten-service allowlist (a test asserts the two lists are disjoint). This does not prove that no other allowed system service can proxy a request for the worker; the complete Mach-service proxy surface is not audited and the local-only guarantee remains unaccepted. **Measured, not assumed:** a deny-by-default profile stops the Metal shader compiler ("No Metal device available") and a read allow-list that starts from "deny everything" aborts Python at start-up, so the profile is allow-by-default with those explicit denials. **It is not a least-privilege profile:** reading system files outside the denied places, IOKit and signals stay allowed. **Residual risks, stated:** `opendirectoryd.libinfo` is the system's user/group/host lookup service and its exact reach on a given macOS version is not audited; the allow-list was measured on one runner (Apple silicon, macOS 26, one small model) and other hardware or models may need more services, in which case the worker fails closed and the model is unavailable rather than the list being widened silently. Treat the macOS boundary as tested direct network/write/private-root denials with the stated gaps, not as a complete sandbox or accepted local-only guarantee.
- The worker gets a clean environment (no secrets), stderr is discarded, only a prompt string goes in and only text comes out (no grants, sources or context objects). A dead, silent or slow worker is a failure, never a hang; a consumer that stops early cancels the worker's generation.
- `MlxEngine` run in-process (development) sets best-effort offline variables only; that is **not** a network guarantee and is documented as such.
- Tests: `tests/test_isolated.py` (inside the worker TCP and UDP sockets are refused while Unix sockets work; the same probe succeeds without the sandbox; clean environment; fail-closed paths; cancel, crash, silence; the whole path through the gateway with the staged folder). Mutation check: removing the seccomp call makes the probe test fail.
- macOS runner tests: `tests/test_isolated.py` (network, write denial, clean environment under `sandbox-exec`) and `tests/test_mlx_native.py` (real MLX load and generation in the sandboxed worker; the real library's process also cannot connect or write).
- Not done: speed, memory and quality measurements on the owner's hardware with the owner's models; a test that the real library makes no network attempt of its own while loading (the OS refusal is what is tested, not the library's intent).
